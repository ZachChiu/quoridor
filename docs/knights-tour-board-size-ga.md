# 騎士巡遊：GA 補「棋盤大小」

大腦筋 11/1 寫。Zach 11/1 說「補上棋盤大小」。

## 為什麼

- 現在 GA 只知道有人在練習、有人在玩節目挑戰，不知道是在哪個大小的棋盤上。
- 想看的是：
  - 練習模式大家選幾×幾、哪個大小最多人完成。
  - 節目挑戰時間到的時候，大家卡在第幾關（6×6、7×7、8×8）。

## 要改的

所有騎士巡遊的 GA 事件多帶一個參數 `board_size`，值是整數 n（6×6 送 6）。

| 事件 | 練習模式 | 節目挑戰 |
|---|---|---|
| `mode_select` | 選的那個大小（`onPractice(n)` 的 n） | 不帶（還沒開始） |
| `game_start` | 這盤的 n | 第一關的大小（6） |
| `game_end` | 這盤的 n | win：最後一關（8）；lose（時間到）：時間到那一刻在第幾關的大小 |
| `game_restart` | 這盤的 n | 重來那一刻在第幾關的大小 |

- 參數名用 `board_size`，不要用 `size`（太泛，以後其他遊戲容易撞到意思不同的值）。
- 送數字，不要送「6×6」字串。
- 其他參數、事件都不動。Wall Go、虎棋不用改。

## GA 後台

大腦筋 11/1 已經在 GA 註冊自訂維度「棋盤大小」（參數 `board_size`，事件範圍）。不用再註冊。

## 驗收

- 上線當下：大腦筋用 GA 的即時報表或隔天 BigQuery 看 `game_start`、`game_end` 有沒有帶 `board_size`。
- 【上線】訊息寫版號、哪幾個事件帶了 `board_size`。大腦筋會記進「判讀數據要記得的事」。
